### 4.2 端口约定：8086 是**有意的**，不是配置错误

> 本节曾把「前端代理 8086 vs 后端默认 8080」记为不一致。补查部署脚本后**修正**：8086 是本项目约定的应用端口，三处独立证据一致。

| 证据 | 内容 |
|---|---|
| 部署脚本 | `observability/scripts/server-apply-app.sh:30` `readonly APP_PORT="${APP_PORT:-8086}"`；`:31` `MGMT_PORT=8087`；健康检查打 `127.0.0.1:${APP_PORT}/api/home`（`:61-62`） |
| 对外入口 | `deploy-app.sh:109` 健康检查 `http://${SSH_HOST}:60084/api/home`；`60084`=商城、`60085`=后台 |
| 两个前端 | `shang-admin-web/vite.config.ts`（`/admin`→8086）、`shang-mall/vite.config.ts`（`/api`、`/admin/files`→8086） |
| 本机实测 | 后端 JVM 正监听 `*:8086` 且返回真实数据（`:8080` 上是**另一个项目** `yy-api-main` 容器） |

**结论**：`application.yaml` 的 8080 只是通用默认值；本项目真实约定是 **8086**。本地联调必须 `SERVER_PORT=8086`——否则后端起来了但两个前端都够不着。→ 已确认 / 机器可复算

### 4.3 ⚠️ 真正的高危项：默认 DB / Redis 端口指向**别的项目**

本机实测的端口归属（`docker ps`）：

| 端口 | 归属 | 风险 |
|---|---|---|
| `5432` | `yy-postgres-main`（**另一个项目** 的 PostgreSQL 16） | 本项目 `application.yaml:11` 默认就是 `localhost:5432` |
| `55432` | `shang-postgres`（**本项目**，pgvector/pgvector:pg16） | 必须显式覆盖才能连对 |
| `6379` | `yy-redis-main`（**另一个项目**） | 本项目默认就是 `localhost:6379` |
| `56379` | `shang-redis`（**本项目**，redis:7） | 必须显式覆盖 |

**后果**：不覆盖 `DB_URL` / `REDIS_HOST`、`REDIS_PORT` 直接启动后端，会**静默连上另一个项目的库**（因为端口通、连接会成功），随后表现为建表/查询行为异常而非启动失败——排查成本极高。→ 已确认 / 机器可复算

    --out "../docs/测试资料/接口文档.md" --diff artifacts/api-doc-diff.md
python3 scripts/build_db_dict.py
# 复算后这两条命令必须无差异，否则机制区文档已过期：
git diff --exit-code -- ../docs/测试资料/接口文档.md artifacts/endpoint-model.json \
    ../docs/06-baseline/01-数据字典.md artifacts/schema-model.json

# ---------- 测试与门禁 ----------
