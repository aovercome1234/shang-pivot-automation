# 接口设计 — V1.0（As-built）

> **给开发看的契约说明**：统一约定 + **关键接口字段与示例** + 全量路径目录。  
> 运行时 OpenAPI：`http://localhost:<端口>/doc.html`（Knife4j）。若与本文冲突，以 Controllers / OpenAPI 为准并回改本文。

---

## 1. 统一约定

### 1.1 传输

| 项 | 约定 |
|---|---|
| Base Path | `/admin/**` |
| Content-Type | `application/json`（上传用 `multipart/form-data`） |
| 鉴权 | Header：`Authorization: Bearer <accessToken>`（login / refresh 除外） |
| 字符编码 | UTF-8 |

### 1.2 统一响应包

所有业务接口外层均为：

```json
{
  "code": 0,
  "msg": "ok",
  "data": {},
  "traceId": "a1b2c3d4e5f6"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | number | `0` 成功；非 0 失败（见错误码段） |
| `msg` | string | 提示文案（失败时给前端 Toast） |
| `data` | object / array / null | 业务载荷 |
| `traceId` | string | 请求追踪 ID |

分页常见 `data`：

```json
{
  "total": 100,
  "records": [ { "...": "..." } ]
}
```

| 字段 | 说明 |
|---|---|
| `total` | 总条数 |
| `records` | 当前页数据 |

分页入参：`page`（从 1）、`size`（默认 10）。前端若传 `pageSize` 会被网关/拦截器映射为 `size`。

### 1.3 错误码段

| 段 | 含义 | 示例场景 |
|---|---|---|
| `40000` | 参数错误 | 缺运单号、拒绝无备注 |
| `40100` | 未认证 / Token 无效 | 未登录、黑名单 |
| `40300` | 无权限 / 禁用 | 账号 DISABLED |
| `40400` | 资源不存在 | 商品/订单 ID 无效 |
| `40900` | 冲突 | 库存不足、非草稿删除、状态机非法 |
| `5xxxx` | 系统错误 | 未捕获异常 |

登录专用：失败次数过多返回锁定类业务码（实现：`ACCOUNT_LOCKED`）。

### 1.4 ID

后端 `Long`；JSON 中请按**字符串**处理，避免 JS 精度问题。

### 2.1 登录

`POST /admin/auth/login`（**无需** Token）

**请求体**

| 字段 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| username | string | 是 | 登录名 | `admin` |
| password | string | 是 | 明文密码（仅传输，服务端 BCrypt 校验） | `Admin@123` |

**请求示例**

```http
POST /admin/auth/login HTTP/1.1
Content-Type: application/json

{
  "username": "admin",
  "password": "Admin@123"
}
```

| 字段 | 类型 | 说明 |

| accessToken | string | 访问令牌 |

| user.roles | string[] | 角色编码 |
| user.permissions | string[] | 权限码 |

### 3.1 分页查询

`GET /admin/users?page=1&size=10&username=&phone=&status=&deptId=`

| 参数 | 说明 |
|---|---|
| username | 模糊 |
| phone | 模糊 |
| status | `ENABLED` / `DISABLED` |
| deptId | 部门 ID |

**响应 `data.records[]` 主要字段**：`id` · `username` · `realName` · `phone` · `email` · `deptId` · `status` · `lastLoginAt` · `roleIds`

### 3.2 创建 / 更新

`POST /admin/users` · `PUT /admin/users/{id}`

**请求体**

| 字段 | 类型 | 创建 | 更新 | 说明 | 示例 |
|---|---|---|---|---|---|
| username | string | 必填 | 一般不可改 | 登录名 | `zhangsan` |
| password | string | 必填 | 可选 | 初始/新密码 | `Admin@123` |

| email | string | 否 | 否 | 邮箱 | `a@b.com` |
| deptId | number | 否 | 否 | 部门 | `1` |

### 4.3 上架 / 下架 / 批量下架 / 删除

| 方法 | 路径 | 说明 |
|---|---|---|
| `PUT` | `/admin/products/{id}/on` | 上架校验：主图、可售 SKU、售价 |
| `PUT` | `/admin/products/{id}/off` | 下架 |
| `PUT` | `/admin/products/batch-off` | Body：`[1,2,3]` 仅处理当前 ON |

```json

```

## 5. 库存

### 5.1 分页查询

`GET /admin/stocks?page=1&size=10&skuId=&warehouseId=&lowOnly=false&warnOnly=false`

| 参数 | 说明 |
|---|---|
| lowOnly | `true` 时只返回**低库存**档：`physical_stock − locked_stock ≤ low_threshold` |
| warnOnly | `true` 时返回**预警档**：低库存 + 关注，即 `physical_stock − locked_stock ≤ low_threshold × 1.5` |

> 两个过滤条件都**下推到 SQL 的 WHERE**（`StockService.page`），因此分页与 `total` 都正确。
> 早期版本在分页之后做页内过滤，会把结果切碎（每页只剩零散几行、total 是当页记录数），已修正。
> 预警档排序：`(physical − locked − low_threshold) ASC`，越缺越靠前，便于照单补货。

**`records[]` 字段**

| 字段 | 说明 |
|---|---|
| id / skuId / warehouseId / warehouseName | 维度 |
| physicalStock | 总库存 |
| lockedStock | 锁定 |
| availableStock | 可售 = physical − locked |
| lowThreshold | 阈值 |
| skuTitle / barCode | SKU 信息 |

### 5.2 调整

`PUT /admin/stocks/adjust`

| 字段 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| skuId | number | 是 | SKU | `1001` |
| warehouseId | number | 否 | 默认 1 | `1` |
| changeQty | number | 是 | 非 0 整数；正入负出 | `10` |
| reason | string | 否 | 服务端可固定为「后台手工调整」 | `后台手工调整` |

**请求示例**

```json
{
  "skuId": 1001,
  "warehouseId": 1,
  "changeQty": 10,
  "reason": "后台手工调整"
}
```

**成功**：`data` = null。  
**失败（破坏不变式）**：

```json
{ "code": 40900, "msg": "调整后违反库存不变式 physical≥locked≥0", "data": null }
```

## 6. 订单发货

### 6.1 列表 / 详情

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/admin/orders` | 分页；可按 status、orderNo |
| `GET` | `/admin/orders/{id}` | `data`: `{ order, items, shipments }` |

### 6.2 发货

`POST /admin/orders/{id}/ship`  
权限码：`order:ship`

| 字段 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| carrier | string | 否 | 默认「模拟快递」 | `顺丰速运` |
| trackingNo | string | **是** | 运单号 | `SF1234567890` |

**请求示例**

```json
{
  "carrier": "顺丰速运",
  "trackingNo": "SF1234567890"
}
```

**成功**：订单 → `PENDING_RECEIVE`；写 shipment；扣库存。  
**失败示例**

```json
{ "code": 40000, "msg": "请录入运单号", "data": null }
```

```json
{ "code": 40900, "msg": "订单状态不允许该操作", "data": null }
```

## 7. 售后审核

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/admin/after-sales` | 分页；status / type / afterSaleNo |
| `GET` | `/admin/after-sales/{id}` | `{ afterSale, order }` |
| `POST` | `/admin/after-sales/{id}/audit` | 审核 |

**审核 Body**

| 字段 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| approved | boolean | 是 | true 通过 / false 拒绝 | `false` |
| remark | string | 拒绝时**必填** | 处理意见 | `凭证不全，请补传` |

**请求示例（拒绝）**

```json
{
  "approved": false,
  "remark": "凭证不全，请补传后重新提交"
}
```

**请求示例（通过）**

```json
{
  "approved": true,
  "remark": "同意退款"
}
```

通过：`PENDING_AUDIT` → `REFUNDING` → `COMPLETED`（沙箱同请求完结）。  
拒绝无备注：

```json
{ "code": 40000, "msg": "拒绝时请填写处理意见", "data": null }
```
