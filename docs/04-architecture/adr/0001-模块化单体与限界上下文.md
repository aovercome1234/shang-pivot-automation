# ADR-0001：采用模块化单体架构，按限界上下文划分（不采用微服务）

- **状态**：Accepted
- **日期**：2026-09-12
- **决策范围**：跨版本基座（全产品线）
- **相关**：`ADR-0004`（Maven 落地）、`docs/00-product/roadmap.md`、`docs/UBIQUITOUS_LANGUAGE.md`

## 背景（Context）

平台定位为**高仿真 Demo**（支付沙箱、不追真实高并发与合规），但目标要求架构按可生产级演进设计。曾讨论是否拆为微服务（网关 + 认证权限 + 电商 + 智能客服）。

微服务在此场景的主要代价：跨服务分布式事务、多进程运维、跨库聚合、小团队维护成本。其收益（独立伸缩、技术异构、故障隔离）在 Demo 无真实规模压力下基本不兑现。

## 决策（Decision）

采用**模块化单体（Modular Monolith）**：单一 Spring Boot 可部署进程，内部按限界上下文划分；工程上以 Maven 多模块落地（见 `ADR-0004`）。

| 限界上下文 | Maven 模块 | Schema | 职责 |
|---|---|---|---|
| identity | `shang-identity` + `shang-identity-api` | `identity` | RBAC、登录态、JWT、审计、文件元数据、字典/配置 |
| commerce | `shang-commerce` + `shang-commerce-api` | `commerce` | 商品/库存/订单/支付/售后/物流 |
| customer-service | `shang-customerservice`（V3.0） | `customerservice` | 会话/Agent/RAG/工单 |
| 公共 / 启动 | `shang-common` / `shang-server` | — | 公共能力；**唯一可执行入口** |

### 硬约束（保证未来可抽取）

1. 跨上下文禁止依赖对方**实现**模块；只依赖 `*-api`（编译期强制，ADR-0004）。
2. 每上下文独立 schema，禁止跨 schema 直读表。
3. 跨上下文只走模块 API 或领域事件，不共享 mapper。
4. 一致性优先本地事务；确需最终一致再用 outbox + 事件。
5. JWT 验签与权限在应用内（ADR-0003）；独立网关可选、非必须。

### 集成关系

- commerce / customer-service 经安全上下文使用 identity 身份，不反向依赖 identity 实现。
- customer-service 的 Agent 查单/物流/售后走 **commerce `*-api`**（进程内），不绕库。
- 坐席 = identity `AdminUser`（坐席角色）。

## 后果（Consequences）

**正面**：单进程 ACID；接缝清晰，未来可按上下文机械抽取服务；构建与演示成本低。  
**负面**：无独立伸缩；需纪律守住「不跨 schema 直读」。

## 演进触发（何时拆服务）

出现真实 QPS/资源隔离/多团队并行部署压力时，将该上下文抽为独立服务：`*-api` → 远程调用 → 独立库 → 服务发现。

## As-built 备注（2026-09）

V1.0 已落地 identity + commerce + `shang-server`；`shang-customerservice` 为空壳预留；**无独立网关进程**，客户端直连 `shang-server`。
