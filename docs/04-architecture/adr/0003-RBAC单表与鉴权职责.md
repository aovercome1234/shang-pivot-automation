# ADR-0003：RBAC 单表模型 + 鉴权职责划分

- **状态**：Accepted
- **日期**：2026-09-13
- **决策范围**：跨版本基座（D1/D2）；业务规则拍板见 D3/D4
- **相关**：`ADR-0001`、`ADR-0002`、`docs/04-architecture/v1.0/数据模型.md`、`docs/04-architecture/v1.0/接口设计.md`

> **文档说明**：本篇为早期「一次拍板」复合 ADR，含 4 项决策（D1～D4）。**新决策请拆独立 ADR**，勿再向本文堆叠无关主题。

## 背景（Context）

早期文档同时出现独立 `menu` 表与 `permission` 表，易双源；网关与应用均写「校验 JWT」职责不清；上架是否要求库存>0 表述冲突；对象存储浏览器访问路径未定。

## 决策（Decision）

### D1. RBAC：只保留 `permission` 单表（取消独立 `menu`）

| type | 含义 | 典型额外字段 |
|---|---|---|
| `DIR` | 侧栏目录 | icon, sort, visible |
| `MENU` | 菜单页 | path, component, icon, sort, visible |
| `BUTTON` | 按钮/操作 | 靠 `code` |
| `API` | 接口权限（可与 BUTTON 共用 code） | — |

- 角色只绑 `permission`（`role_permission`）。
- 侧栏：`type IN (DIR, MENU)` 且 `visible=true` 的树。
- 按钮 / `@PreAuthorize`：用 `code`（如 `product:add`）。
- 后台 UI：「菜单与权限」一页维护树；角色页勾选同源权限树。

### D2. 鉴权职责

| 组件 | 做 | 不做 |
|---|---|---|
| **Gateway**（可选） | 路由、限流、透传 `X-Trace-Id`；可对缺 Token 粗拦 401 | **不**验签、**不**查黑名单、**不**注入权限 |
| **shang-server（identity Filter）** | 验签、过期、Redis 黑名单（jti）、`clientType`、`SecurityContext`、方法级鉴权 | 不假设「网关已认证」 |

本地可直连 app；若上网关，鉴权真相仍在应用内。

### D3. 商品上架与库存

- 上架校验：主图 + 价格合法 + 至少一个可售状态 SKU。
- **允许**可售库存为 0 时上架；C 端可展示，**下单时**校验 `availableStock >= qty`。
- 不要求「库存>0 才能上架」。

### D4. MinIO 浏览器访问

- 公开对象：经 Nginx / Gateway 反代（如 `/oss/**`），规避 CORS、隐藏内网 endpoint。
- 预签名 PUT：MinIO API 或同反代写路径；服务端用内网 endpoint。

## 后果（Consequences）

- 菜单/权限单源；踢人与黑名单集中在 identity。
- 上架与下单规则一致，可先上架再补货。
- Gateway 保持轻量；未部署时不影响直连调试。
