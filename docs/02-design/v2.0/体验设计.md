## 1. 体验一句话

顾客在 **尚品汇** 里：**逛首页 → 分类挑货 → 看详情选规格 → 加购结算 → 支付（沙箱）→ 查订单**。
同一套品牌色，**Web 宽屏**和 **H5 竖屏**信息一致、布局不同 —— 下面每组都是 **左 Web / 右 H5**，方便对照。

---

## 2. 顾客怎么走（地图）

```text
游客：首页 → 分类 → 详情 ──(要加购)──► 登录
登录后：购物车 → 确认订单 → 支付 → 订单列表 →（可选）售后 / 评价
我的：个人中心 / 地址 / 收藏 / 足迹
```

| 画幅 | 约定 |
|---|---|
| Web | 设计宽约 1440；分类商品约 4 列；购物车「左清单 + 右结算」 |
| H5 | 截图 390×844；商品约 2 列；列表触底加载；登录与规格选择用半屏弹层 |

## 4. 点下去会发生什么（C 端弹窗图鉴）

C 端的所有弹层一次性排好：**Web 用居中对话框，H5 用底部半屏**。

| Web 弹窗图鉴（33 个样例） | H5 弹窗图鉴（34 个样例） |
|---|---|
| ![Web 弹窗图鉴](../../01-requirements/shots/store-web-dialogs.png) | <img src="../../01-requirements/shots/store-h5-dialogs.png" alt="H5 弹窗图鉴" width="280" /> |

分七组覆盖全链路：登录层 → 规格选择 → 购物车增删 → 结算与支付四态 → 订单操作 → 售后与评价 → 轻提示。

> ✅ **图鉴 = 现状**：规格选择层、支付四态、评价表单、缺货禁用态均已在 C 端实现，与图鉴一致。对齐台账见 PRD-V2 §10.A。

### 最容易踩的三个交互

| 场景 | 应该怎样 |
|---|---|
| 游客点加购 | 半屏登录 → 成功后**回到刚才那件商品**，已选规格不丢 |
| 库存不足 | 轻提示「库存不足」，数量停在最大可售，不把价格改掉 |
| 支付 | 「支付中」→ 成功 / 失败（可重试）→ 结果页，全程能看出钱到哪一步了 |

## 6. 购物时的手感

| 场景 | 应该怎样 |
|---|---|
| 主按钮 | 暖琥珀底 + 深色字 |
| 价格 | 等宽数字 + 珊瑚色 |
| 加载 | 商品卡骨架屏 |
| 空购物车 / 空列表 | 「去逛逛」 |
| 未登录加购 | H5 半屏登录；成功后回到刚才的事 |
| 规格没选 | 先提示，再允许下单 |
| H5 列表 | 触底加载；底部留出安全区 |
| 弹层 | Web 居中、H5 半屏；危险操作要二次确认 |
