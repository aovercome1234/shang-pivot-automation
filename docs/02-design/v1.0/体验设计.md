## 1. 体验一句话

运营每天在这套界面里完成：**登录 → 管人管权 → 上架商品 → 调库存 → 发货 / 审售后 → 看日志改配置**。
界面是**左导航 + 顶栏 + 表格为主**的工作台，奶油底、暖橙强调，偏密、好扫数据。

## 3. 菜单结构（用户怎么找功能）

侧栏由**权限**决定谁能看见什么。V1 信息架构如下（菜单名 = 页面标题，不换词）：

```text
概览   → 工作台
商品中心 → 商品列表 / 类目与品牌 / 库存管理
订单中心 → 订单列表 / 售后管理
系统管理 → 用户 / 角色 / 菜单与权限 / 部门 / 字典 / 操作日志 / 系统设置
```

**两条最常用路径：**

1. **上架**：类目与品牌 → 商品列表新增（含 SKU）→ 调库存 → 上架
2. **履约**：待发货订单 → 发货；售后单 → 同意 / 拒绝

## 5. 点下去会发生什么（弹窗图鉴）

V1 的全部弹窗、抽屉、确认与拒绝提示，一次性排在一页里 —— 这是设计评审与验收的**唯一弹窗来源**：

![弹窗与交互图鉴](../../01-requirements/shots/dialogs.png)

共 **53 个样例**（50 弹窗 + 3 抽屉），按模块分组，每条都标了「怎么触发」。翻这页能立刻看出全站的交互语气是否一致。

> ✅ **图鉴 = 现状**：本版已完成「原型改 → 实现跟」的对齐，53 个样例（含抽屉形态与全部拒绝类弹窗）都已在管理端实现。实现与原型的一致性台账见 PRD §10.A。

### 五类弹窗（全站统一）

| 你遇到的是… | 长这样 | 按钮 |
|---|---|---|
| 做件可逆的事（启用、保存） | 中性图标 + 说清后果 | 取消 / 确认 |
| 做件破坏性的事（删除、下架、发货） | 警示色图标 + 把对象名字写进标题和正文 | 取消 / 红色确认 |
| 填一份表单（新增、编辑、发货、审核） | 表头 + 字段 + 说明块 | 取消 / 保存 |
| 输入一个值（重置密码、改密钥） | 单输入框 + 约束说明 | 取消 / 保存 |
| 系统不让你这么做（状态不对、被引用、校验不过） | 只有「知道了」，不给「取消」以免以为能重试 | 知道了 |

**填错了会怎样**：字段级错误是**框下面的红字**，弹窗不关；业务级错误（比如上架缺主图）在弹窗里**一条条列清楚**，方便一次改完。

## 6. 操作时的「手感」约定

这些规则保证每个列表页、表单页行为一致：

| 你在做什么 | 界面应该怎样 |
|---|---|
| 填表 | 必填带 `*`；错了红字在框下面 |
| 删除 / 禁用 / 发货 | 先弹确认，文案里带上对象名字 |
| 点保存 | 按钮转圈禁用；成功 / 失败出 Toast |
| 等列表 | 出骨架屏，不要空白干等 |
| 没数据 | 引导按钮，如「去新增」 |
| 翻页 | 默认每页 10 条，分页贴底 |
| 看金额数量 | 右对齐、等宽数字字体 |
| 敏感配置 | 密钥打码，不要回显原文 |

动效克制：大约 150ms 的过渡，不要花哨。

改了原型外观 → 跑一次渲染脚本 → 本文引用自动更新。功能规则、字段与验收不在本文，而在 PRD §8。
