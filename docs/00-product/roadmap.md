# 产品版本规划（Roadmap）— Shang Pivot

> 产品战略**唯一正文**。术语见 [`docs/UBIQUITOUS_LANGUAGE.md`](../UBIQUITOUS_LANGUAGE.md)；架构决策见 `docs/04-architecture/adr/`。

## 0. 产品是什么（读这一段就够）

| 项 | 说明 |
|---|---|
| 定位 | 高仿真电商 Demo：后台供给 + C 端交易 +（后续）智能客服 |
| 工程 / 后台名 | Shang Pivot；界面文案「Shang 商城后台」 |
| C 端品牌 | **尚品汇**（自 V2.0）；Slogan「选好物，享生活」 |
| 目标 | 闭环可演示、分版本可验收、架构可演进（模块化单体） |
| 不做（首期） | 真实支付清结算、真高并发多机房、自训大模型 |

策略：**供给 → 交易 → 服务**。V1 供给，V2 交易，V3 客服依赖交易数据。

## 1. 版本时间线（先读规则，再看表）

```text
V1.0 ──► V2.0 ──► V3.0 ──► V4.0
           └────► V2.1（小程序，V2 的分支）
```

**文档与产物的版本纪律（红线）**

1. **时间线单向**：先写的版本不能出现后写版本的内容。**V1 文档不得含 V2 内容**；V2 文档可以含 V1 内容（V1 是它的基线），但**不得含 V3 / V4 内容**。反向混入即视为串档，必须修正。
2. **后版本只「引用」前版本，不「重述」**：V2 文档讲新增与改动，V1 已交付且未改的部分只给链接。
3. **范围表必须标目标版本**：写「不做」时要写明它属于哪一版（如「优惠券（V4.0）」），否则读者无法判断是遗漏还是延期。
4. **原型按版本裁剪**：后台原型用 `.stitch/原型/admin/sidebar.js` 的 `__NAV_VERSION__='v1'|'v2'` 控制侧栏；V1 页面截图里**不允许出现后续版本菜单**。
5. **截图可重放**：全部截图由 `.stitch/原型/render-shots.mjs` 生成，改原型后跑一次即可，避免「文档里的图和原型对不上」。
6. **数据也算产物**：种子数据要能演示该版宣称的功能（例：宣称有库存预警 → 种子里必须有低库存行；宣称可删草稿 → 种子里必须有草稿商品）。

## 3. 各版本要点

### V1.0 — 后台（已交付 As-built）

- **有**：RBAC、类目·品牌·商品（32 SPU / 47 SKU，含草稿与下架）、库存三态与两档预警、演示订单发货、售后审核、配置 KV、MinIO、操作日志、工作台、51 个弹窗样例。
- **无**：C 端、出入库单据、定时上架、订单导出、会员与运营位（→ V2.0）。
- **文档**：PRD `01-requirements/PRD-V1.0-后台管理.md` · 体验 `02-design/v1.0/体验设计.md` · 设计 `04-architecture/v1.0/` · ADR `04-architecture/adr/`

### V2.0 — 购物（已交付）

- **有**：尚品汇 Web/H5 浏览下单沙箱支付；订单/售后/评价/地址/收藏/足迹；后台站点品牌、首页运营位、交易配置、会员冻结、评价管理、出入库单、定时上架、订单增强。
- **对 V1 的改动仅三处**：订单列表（筛选与导出增强）、商品编辑（上架方式）、系统设置（加交易分组）。其余 V1 页面零改动。
- **无**：小程序（V2.1）、智能客服（V3.0）、优惠券/促销/自由装修（V4.0）。
- **文档**：PRD `PRD-V2.0-购物网站.md` · 体验 `02-design/v2.0/体验设计.md` · 设计 `04-architecture/v2.0/`

### V2.1 — 微信小程序

- 复用 V2 业务与接口，多端登录态隔离（`clientType`）；依赖 V2.0 完成。

### V3.0 — 智能客服

- **设计主源**：`03-ai/customer-service-智能客服.md`（PRD 届时按模板新建）。
- **本版之前不得出现**：客服入口、会话、坐席、工单、知识库等任何 V3 概念（含配置项与占位入口）。

### V4.0 — 营销与装修（可选）

- 优惠券 / 促销 / 直播 / 自由装修；依赖 V2。
- **本版之前不得出现**：券、秒杀、补贴、直播间、拖拽装修等任何 V4 概念。
