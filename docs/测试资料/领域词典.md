# 尚品汇（Shang Pivot）领域词典 v1.0

> 用途：用例预期中的**状态词/枚举/错误码**必须引用本词典词条（lint R27 机器核对）；不可自行发明词条。
> 词条出处：`backend/shang-common/.../result/ErrorCode.java`（错误码全集）+ `backend/**/application/*.java` 状态赋值处 + Flyway `V1~V19` + 现有《接口文档》《需求文档》。
> 整理日期：2026-10-05。

---

## 0. 响应信封与成功码

统一响应体 `{ code, msg, data, traceId }`（`Result`）。**成功业务码 = `0`**（`ErrorCode.SUCCESS(0,"success")`），失败码见 §9。
注意：本项目**成功码不是 200**，与元气购不同；用例正向预期业务码一律写 `0`。

## 1. 订单（`commerce.order.status`，字符串）

| 词条 | 语义 | 合法流转 |
|------|------|----------|
| PENDING_PAY | 待支付（下单后初始态） | → PENDING_SHIP（沙箱支付）/ → CLOSED（超时关闭） |
| PENDING_SHIP | 待发货（支付成功置入） | → PENDING_RECEIVE（管理员发货） |
| PENDING_RECEIVE | 待收货（发货置入） | → COMPLETED（确认收货）/ 可申请售后 |
| COMPLETED | 已完成 | 终态；可申请售后 |
| CLOSED | 已关闭（超时未支付，`OrderSubmitService` 定时任务置入） | 终态 |

**状态机用例断言要求**：流转类用例必须写明"从 X 到 Y"，并断言非法流转被拒绝（`ORDER_STATUS_INVALID`）。

## 2. 支付（`commerce.payment`）

| 词条 | 语义 |
|------|------|
| PAID | 支付成功（沙箱支付写入，`paid_at` 同时落库） |
| SANDBOX | 支付渠道（`channel`）；`trade_no` 形如 `SANDBOX-{orderId}` |

支付开关来自系统配置 `payment.sandbox.enabled`（默认 `true`）；关闭时支付返回 `CONFLICT`。

## 3. 售后（`commerce.after_sale`）

| 词条 | 语义 | 可审核 |
|------|------|--------|
| PENDING_AUDIT | 已提交待审核（申请后初始态） | ✅ |
| REFUNDING | 退款中（审核通过瞬间的中间态，同事务内立即转 COMPLETED） | ❌ |
| COMPLETED | 已完成（审核通过并模拟退款完结） | ❌ |
| REJECTED | 审核驳回 | ❌ |

申请类型 `type`：`REFUND`（仅退款）/ `RETURN_REFUND`（退货退款）/ `EXCHANGE`（换货）。
可申请前置订单状态：`PENDING_RECEIVE` / `COMPLETED`。

**状态机用例断言要求**：非 `PENDING_AUDIT` 再次审核必须被拒绝（`AFTER_SALE_STATUS_INVALID`）。

## 4. 商品

- `commerce.spu.status`：`DRAFT`（草稿）/ `ON`（上架）/ `OFF`（下架）
- `commerce.sku.status`：`ENABLED`（启用）
- `commerce.category.status` / `commerce.brand.status`：`ENABLED`
- `commerce.attribute.type`：`SPEC`（规格属性，默认值）

## 5. 库存（`commerce.stock` 三态）

- 物理库存 `physical_stock` ≥ 锁定库存 `locked_stock` ≥ 0；**可售 = 物理 − 锁定（不落库）**
- `commerce.stock_log.type`：`INIT`（建档初始化）/ `LOCK`（下单锁定）/ `UNLOCK`（取消解锁）/ `SHIP`（发货扣减）/ `ADJUST`（人工调整）
- `commerce.in_out_order.type`：`PURCHASE_IN`（采购入）/ `STOCKTAKE`（盘点）/ `SALE_OUT`（销售出，发货自动生成）

## 6. 会员与账号

- `identity.customer.status`：`NORMAL`（正常）/ `FROZEN`（冻结）
- 管理端 `admin_user` / `role` / `dept` / `permission` / `dict_item` / `warehouse` 的 `status`：`ENABLED`（启用）
- 管理端角色代号：`SUPER_ADMIN`

## 7. 评价（`commerce.review.status`）

| 词条 | 语义 |
|------|------|
| VISIBLE | 可见（发表后默认） |
| HIDDEN | 已隐藏（管理员隐藏操作） |

评分 `rating` 取值 1–5；同一订单项重复评价返回 `REVIEW_EXISTS`。

## 8. 内容运营（`commerce.home_slot` / `home_slot_item.status`）

`ON`（投放中）/ `OFF`（已下线）。首页运营位按 `code` 取。

## 9. 错误码全集（源码 `ErrorCode.java`，共 18 个）

| 错误码 | 数值 | 典型场景 |
|--------|------|----------|
| SUCCESS | 0 | 成功（业务码 0） |
| BAD_REQUEST | 40000 | 参数校验失败、必填缺失、格式非法 |
| UNAUTHORIZED | 40100 | 未登录 / 无有效令牌 |
| LOGIN_FAILED | 40101 | 账号或密码错误、验证码错误 |
| TOKEN_EXPIRED | 40102 | 令牌过期 |
| TOKEN_INVALID | 40103 | 令牌无效 |
| ACCOUNT_LOCKED | 40104 | 账号锁定（连续失败） |
| FORBIDDEN | 40300 | 无权限 |
| CUSTOMER_FROZEN | 40310 | 会员冻结，账号不可用 |
| NOT_FOUND | 40400 | 通用资源不存在（含文件对象读取失败） |
| PRODUCT_UNAVAILABLE | 40410 | 商品不存在或未上架 |
| CONFLICT | 40900 | 状态不允许（如沙箱支付未开启） |
| STOCK_INSUFFICIENT | 40901 | 库存不足 |
| ORDER_STATUS_INVALID | 40902 | 订单状态不允许该操作 |
| AFTER_SALE_STATUS_INVALID | 40903 | 售后状态不允许该操作 |
| REVIEW_EXISTS | 40904 | 该订单项已评价 |
| SYSTEM_ERROR | 50000 | 系统异常 |

## 10. 机器可读词表（lint R27 使用，勿删本行）

机器可读词表：SUCCESS BAD_REQUEST UNAUTHORIZED LOGIN_FAILED TOKEN_EXPIRED TOKEN_INVALID ACCOUNT_LOCKED FORBIDDEN CUSTOMER_FROZEN NOT_FOUND PRODUCT_UNAVAILABLE CONFLICT STOCK_INSUFFICIENT ORDER_STATUS_INVALID AFTER_SALE_STATUS_INVALID REVIEW_EXISTS SYSTEM_ERROR PENDING_PAY PENDING_SHIP PENDING_RECEIVE COMPLETED CLOSED PAID SANDBOX PENDING_AUDIT REFUNDING REJECTED REFUND RETURN_REFUND EXCHANGE DRAFT ON OFF ENABLED SPEC INIT LOCK UNLOCK SHIP ADJUST PURCHASE_IN STOCKTAKE SALE_OUT NORMAL FROZEN VISIBLE HIDDEN SUPER_ADMIN

反向检查豁免：SYSTEM_ERROR SUCCESS SANDBOX ON OFF

> 豁免理由（每条都是"记法约定"或"不可达"，不是覆盖缺口）：
> - `SYSTEM_ERROR`：系统级兜底码，正常用例不应触发（触发即缺陷）；
> - `SUCCESS`：项目约定成功业务码写 `0`（§11 规则 4），用例不写词条名；
> - `SANDBOX`：沙箱支付以路径 `/api/payment/sandbox`（小写）体现；
> - `ON` / `OFF`：商品上下架状态在用例中以中文「上架/下架」表达。
>
> 除上述外，未被任何用例触发的词条由 R36 报 warn，须补用例或补断言（记入 `artifacts/coverage-gap.json`）。

## 11. 使用规则

1. 用例的「预期业务码/断言」中出现的大写词条（自动识别为 `[A-Z][A-Z_]{3,}`）必须属于 §10 词表；
2. 需要新增词条时：先更新本词典（附源码/契约出处），再改用例；
3. 状态机类断言必须符合 §1–§8 的流转表；"从 X 到 Y" 中 X、Y 均须为词典词条；
4. 成功业务码统一写 `0`（不是 200）；负向写 `error.code=<词条>`；
5. 数值型业务码（如 `40000`）允许出现在断言中以佐证词条，但「预期业务码」列优先写词条名。
