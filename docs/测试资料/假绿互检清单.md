# 假绿互检清单（尚品汇）

> 用途：每次跑批后逐条互检，专治"看着是绿的、其实没测到"。**机检项**由脚本强制，**人检项**须在留痕里留证据。
> 出处：元气购对照文档 §6-⑥（对方实测的 8 条假绿/掩盖模式）。落地位置：`scripts/release_gate.py` / `scripts/case_lint.py` / `conftest.py` / `scripts/zentao_sync.py`。

| # | 假绿模式 | 后果 | 判定方式 | 落地 |
|---|----------|------|----------|------|
| 1 | **结果文件被 `touch` 刷时间** | 没跑也过"新鲜度" | 机检：C8 按 `finished_at`（不是 mtime）算龄，且结果文件须带 `run_id` | `release_gate.py` C8 |
| 2 | **结果文件与 junit 不同批**（手改结果、只重跑单条） | 报"通过"的其实没跑 | 机检：结果内记录的 `junit_sha256` 必须等于当前 `junit.xml` 摘要 | `release_gate.py` C8 / `conftest.py` |
| 3 | **多 nodeid 同名用例互相掩盖**（后写覆盖前） | 同一用例一次红一次绿 → 报绿 | 机检：C3 采用"任一失败即失败"，不做 last-write-wins | `release_gate.py` C3 |
| 4 | **lint 读旧报告**（改了清单没重跑） | 报 fail 0 但清单已变 | 机检：C1 每次**现场重跑** lint，不读历史报告 | `release_gate.py` C1 |
| 5 | **门禁依赖缺失静默失效**（词典/接口文档/端点模型读不到） | 规则没启用，报 fail 0 | 机检：依赖缺失 → `case_lint.py` 退出码 2，拒绝出结论 | `case_lint.py main()` |
| 6 | **登记表空登记**（写个用例 ID 就算"已登记"） | 失败脱管 | 机检：C3 要求每条登记带 `defect` + `reason`，空登记视为未登记 | `release_gate.py` C3 |
| 7 | **跳过被渲染成通过**（禅道 `n/a` 显示为 pass） | 没跑的用例在禅道是绿的 | 机检：回写映射 `skipped → blocked`（不是 `n/a`） | `zentao_sync.py` |
| 8 | **评审结论被脚本代填**（自动写"通过"凑 100%） | C6 假绿 | 机检：`review_workbench.py` 只预填事实、结论列留空；C6 读人填的 `p0_reviewed` | `review_workbench.py` / `release_gate.py` C6 |

## 每轮跑批后的互检动作

1. `python3 scripts/release_gate.py` → 看 C8 的 `run_id` 是否等于本轮 `run_automation.py` 打印的 RUN_ID（不等 = 有人拿旧结果充数）。
2. `python3 scripts/case_lint.py` → 首行须打印"规则启用：…"（不打印 = 依赖缺失，结论无效）。
3. 对账：`python3 scripts/reconcile.py --json` → `verdict=PASS` 且三项差集均为 0（或已豁免）。
4. 禅道回读：抽查 3 条 `lastRunResult`，与 `artifacts/automation_results.json` 逐条对齐（防回写丢批）。
5. 词典反向：`artifacts/coverage-gap.json` 的 `untested_terms` 是否为空（非空 = 有词条从没被测过）。

## 已知未覆盖的互检项（本轮如实标注）

- 第 2 条只绑定 junit 摘要，**不防"重跑同一份清单但环境变了"**（如部署了修复后结果变化）→ 靠 `run_id` 人工比对。
- 第 8 条只保证"脚本不代填"，**不保证填的人是独立评审人**（本轮评审为证据驱动首过，非独立人工复核，已在台账 `method` 字段注明）。
