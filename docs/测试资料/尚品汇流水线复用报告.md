## 5. 遇到的问题与解法

| # | 问题 | 影响 | 解法 |
|---|---|---|---|
| 1 | 线上 60084/60085 **未暴露** `/v3/api-docs`（返回 SPA index） | 拿不到线上 OpenAPI | 用本机同源实例 `127.0.0.1:8086/v3/api-docs` 导出；先逐模块 `diff` 确认运行代码与目标仓库 `src` 完全一致（6 模块差异 0） |
| 2 | 端点解析把 `"/{id}"` 当成数组语法，`{}` 被剥掉 | 源码端点集错误（交集仅 82/135） | 修正 `extract_paths`：仅当整体以 `{` 开头才按数组解析 → 135/135 对齐 |
| 3 | **幂等类 78 条用例的「预期HTTP」写成 `HTTP=200`**（应为 `200`） | lint 未拦截，会污染禅道字段 | 抽样验收时发现 → 修正模板常量并全量重生成 |
| 4 | 「缺少必填参数」预期与实际不符（源码仅 5 处 `@Valid`，47 处请求体未声明 required） | 38 条参数用例预期可能错误 | 建立 `endpoint-model.json`（源码派生 `param_enforced`）；仅对"有路径参数 或 @Valid 或显式 `BAD_REQUEST`"的 75 个端点出参数用例；同步修正 R15 适用性判定 |
| 5 | Map 型请求体渲染成 `请求体：{}`（24 条） | 用例不可执行 | 从 Controller 源码 `body.get("x")` 派生字段名 + 取值约定；服务层消费的 `PUT /admin/site/brand` 用显式覆盖 → 空请求体降为 **0** |
| 6 | 禅道标题把 `/` 存成 `\/` | 在线核对 10 条**误报** | R20 比对前归一化转义（同时优化违规消息展示） |
| 7 | 部分端点无 `@Operation` summary，标题退化成 `GET /api/...` | 标题非业务语言 | 增加 method-aware 中文回退名表（35 个 C 端端点） |
| 8 | 同 summary 端点标题冲突（如 `/api/auth/login` 与 `/phone`） | 生成器断言失败 | 模块名去重：同 summary 多端点时追加路径末段 |
| 9 | R15 靠标题含「缺少」识别参数维度 | 改标题后 20 条误报 | 标题统一回规范用词「缺少必填参数」 |
| 10 | `lint_selftest.py` 样例是元气购约定（`/v1`、成功码 200） | 自测必然失败 | 样例改造为尚品汇约定（`/api`、成功码 0、失败 `HTTP 200`），26/26 通过 |
| 11 | 试点子集不满足 R15 覆盖矩阵 | 上传被 lint 门禁拦截 | 试点用 `--skip-lint` 并记录理由；**全量上传走完整 lint 门禁**（upload 日志显示 fail 0 后放行） |

## 6. 遗留项与下一步建议

### 6.1 本轮明确不做（用户决策点 4）

- 用例评审（P0 全评 / P1 抽评 ≥30%，《评审方案.md》流程）
- 自动化框架接线（pytest 夹具、造数工厂、动态断言引擎、结果回写）

### 6.2 已知限制

| 项 | 说明 |
|---|---|
| `INF-03`（API 文档）无自动化用例 | springdoc 自动端点不在 135 个 Controller 端点内，造用例会破坏"源码=OpenAPI"0 差异门槛；标注为治理说明 |
| 禅道无「清理」「备注」字段 | 只推送 title/precondition/steps/expects（含预期 HTTP、业务码、断言）；`test_cases_inventory.md` 始终是唯一内容源 |
| MinIO 未部署 | `POST /admin/files/*`、`/api/files/*` 的**执行**会失败（环境限制，非用例缺陷）；用例本身按契约编写 |

### 6.3 建议下一轮优先处理的环境缺陷（执行时会被用例捕获）

| 现象（已实测） | 期望 | 位置 |
|---|---|---|
| 无效 Token → **HTTP 500**（框架级错误体，非统一信封） | 401 + `TOKEN_INVALID` | `JwtAuthFilter` |
| 请求体缺失（不传 body）→ **HTTP 500** | 400 + `BAD_REQUEST` | `GlobalExceptionHandler` 缺 `HttpMessageNotReadableException` 分支 |
| `POST /api/reviews` 非数字 `rating` → `NumberFormatException` | 400 + `BAD_REQUEST` | `StorefrontController.createReview` |

### 6.4 建议流程

1. 先修 §6.3 的 3 个缺陷（都会让 P0 用例在首次执行时失败）；
2. 补上 MinIO（`docs/05-assets/product/*.jpg` → `PRODUCT/seed/`），否则文件类用例无法执行；
3. 执行《评审方案》完成抽查；
4. 接入自动化执行框架（可复用 `api_testcases/tests/`、`core/`、`run_automation.py` 骨架，替换数据工厂与角色解析）。
