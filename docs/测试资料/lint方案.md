# 用例 Lint 方案（质量门禁）

> 目的：把《rule.md v2.0》的规范从"文档约束"变成"机械校验"，让质量问题在上传禅道之前被拦截。
> 状态：方案已定稿（2026-10-04），**待实施**。实施步骤见 §5。

---

## 1. 定位与目标

- **门禁**：用例清单每次变更后、上传禅道前必须执行；有 `fail` 级违规时**禁止上传**。
- **目标**：标题规范、字段完备、预期确定性、数据可执行、覆盖可证——五类问题全部机械化可查。
- **原则**：只读检查，不改数据；报告给出 case_id + 字段 + 证据，便于修复。

## 2. 输入与输出

| 项 | 说明 |
|----|------|
| 主输入 | `test_cases_inventory.md`（唯一内容源，直接解析 14 列） |
| 辅助输入 | 《接口文档.md》的接口清单（METHOD+路径，R14 对照用，可自动提取） |
| 在线模式 | `--online` 时登录禅道核对 keyword 与标题同步（R19/R20） |
| 输出 | `artifacts/lint/lint-report.json` + `lint-report.md`（按 severity 分组，含修复建议） |
| 退出码 | 0=全过（无 fail）；1=存在 fail；2=输入/登录错误 |

## 3. 规则清单（R01–R20）

**级别说明**：`fail`=阻断上传；`warn`=提示整改，不阻断。

| 编号 | 级别 | 检查 | 违规示例 |
|------|------|------|----------|
| R01 | fail | 标题三段式：恰好 2 个 `_`，三段均非空 | `删除商品_失败`（2 段） |
| R02 | fail | 标题全库唯一 | 两条同名 |
| R03 | fail | 标题禁词：`HTTP`、`code=`、错误码枚举（UNAUTHORIZED/VALIDATION_FAILED/STATE_INVALID/PENDING 等）、`待确认`、`API-AUTO`、以 `_id` 结尾、独立数字 `400/404/500` | `…_HTTP 400 + UNAUTHORIZED` |
| R04 | fail | 稳定ID格式：契约 `^{METHOD}_{路径}-\\d{3}$`、业务 `^BUS-[A-Z]+-\\d{3}$` | `delete_1-003` |
| R05 | fail | 稳定ID全库唯一 | 重复ID |
| R06 | fail | 预期确定性：预期HTTP/预期业务码/断言列禁 `待确认/TBD/待定/4xx/符合约定` | `4xx（具体状态待确认）` |
| R07 | fail | 必填列非空：用例ID/优先级/类型/标题/前置条件/请求方法/请求头/参数/步骤/预期HTTP/预期业务码/断言/清理 | 清理列为空 |
| R08 | fail | 清理有效性：非空；只读用例允许字面量 `无需清理（只读）`；写操作用例须含动作词（删除/还原/关闭/移除/撤销之一） | 写操作用例清理=`无` |
| R09 | warn | 参数占位符：`<>` 包裹、空值模式 `{"account":""}`、`<unique>` 等 | `{"account":"<test>"}`（须改为取值约定） |
| R10 | warn | 固定数据库ID：`[Ii]d\s*[:=]\s*\d+`（示例值显式标注"示例"可豁免） | `{"addressId":1}` |
| R11 | fail | 环境硬编码：IP 正则（`\\d+\\.\\d+\\.\\d+\\.\\d+`）、`localhost`、`:6\\d{4}` 端口 | `http://111.170.33.2:60080` |
| R12 | warn | 数据准备启发式：前置含"已有/存在"且涉及 购物车/地址/订单/售后/账号/收藏 时，须含准备方式（含"由/生成/准备/前置步骤/构造"之一） | "有 checked=1 购物车项"（未写怎么准备） |
| R13 | fail | 方法路径合法：METHOD ∈ {GET,POST,PUT,DELETE,PATCH}；路径以 `/v1/` 开头、不含 `/api/` | `/api/v1/products` |
| R14 | warn | 路径存在于接口文档清单（R13 的路径集合） | 文档中不存在的路径 |
| R15 | fail | 覆盖矩阵：每个接口（METHOD+归一化路径，`{x}`→`{id}`）必须齐 **正向/未带Token/缺少必填参数/重复提交** 4 类；有分页参数的接口加"边界"1 类。缺项输出缺口表 | 某接口无"未带Token"用例 |
| R16 | warn | 优先级分布：P0 占比 >40% 告警 | 当前 70% → warn |
| R17 | fail | 优先级合法值 ∈ {P0,P1,P2,P3} | `高` |
| R18 | warn | 断言丰富度：断言列 <10 字符或不含任一词（`=`/`包含`/`非空`/`一致`/`不含`/`为`） | "断言=成功" |
| R19 | fail | 在线核对（`--online`）：禅道 keyword == `API-AUTO,<稳定ID>`（232/232） | keyword 丢失 |
| R20 | fail | 在线核对（`--online`）：禅道标题 == 清单标题（防清单/禅道漂移） | 标题不一致 |

## 4. 实现方案

- **形态**：单文件 `scripts/case_lint.py`（Python 3.9+，离线模式零第三方依赖）。
- **结构**：
  ```
  parse_inventory(path) -> List[Record]        # 复用 zentao_sync 的解析逻辑（14列）
  extract_api_catalog(接口文档.md) -> Set[接口] # R14：从文档表格/标题提取 METHOD+path
  RULES = [r01, r02, ...]                       # 每条规则：fn(records, ctx) -> List[Violation]
  report(violations) -> json + md               # 按 severity 分组、按 case 聚合
  main()                                        # CLI：--inventory --doc --online --strict
  ```
- **CoverageMatrix（R15）**：按 `METHOD + 归一化路径` 分组清单记录，用"场景段"分类（典型请求→正向、未带Token→鉴权、缺少必填/路径参数→参数、重复提交系列→幂等、非法分页→边界），输出：接口 × 5 类 的 ✓/✗ 矩阵与缺口清单。
- **集成点**：
  1. 本地/CI：每次修改清单后运行；`fail>0` 直接非零退出；
  2. 上传门禁：`zentao_sync.py upload-cases / repair-cases` 开头调用 lint（子进程或 import），fail 即中止；
  3. 报告归档：`artifacts/lint/`（与 preflight/rename 报告同级）。
- **性能**：232 条离线 <1 秒；在线模式 ≤3 次请求（browse 一页 + 登录）。

## 7. 增量规则（尚品汇 v1.1，2026-10-05）

> 背景：首轮 478 条用例虽离线 lint fail 0，但人工质量核查发现**"形式合规、事实不成立"**的三类缺陷：
> 断言指向不存在的接口、清理引用不存在的端点、请求体字段不足。这三类 lint 原本都拦不住，
> 因为它们检查的是"形状"（有没有 `回查` 二字、有没有动作词、字段非空），不是"事实"。
> 为此新增 R31–R33，把"事实"也变成机械可查——依赖 `artifacts/endpoint-model.json`（由 `build_api_doc.py` 从**源码**派生）。

| 编号 | 级别 | 检查 | 依赖事实 | 违规示例 |
|------|------|------|----------|----------|
| R31 | fail | 断言中的 `回查 <METHOD> <path>` 必须存在于接口清单 | `endpoint-model.json` 的端点全集（路径归一化 `{x}`→`{id}`，忽略 query） | `回查 GET /admin/attributes/{id}`（该详情接口不存在） |
| R32 | fail | 清理列中「调用」引用的端点（DELETE/POST/PUT）必须存在于接口清单 | 同上 | `用例结束后调用 DELETE /admin/auth/login/{id} 移除…` |
| R33 | fail | 请求体（可解析为 JSON 时）必须覆盖源码声明的必填字段 | 端点的 `dto_required`（源码 `@NotBlank/@NotNull/@NotEmpty`） | `POST /admin/auth/login` 请求体缺 `password` |
| R34 | fail | 请求体字段名合法性（禁 `@` 前缀与中文键名） | 无（防内部标记泄漏） | `{"@cartItemId": …, "@quantity": …}` |
| R35 | fail | 幂等用例必须标注策略的源码出处（备注含「幂等策略：源码 <文件:行> <依据>」） | 无（防无依据的默认策略漂移） | 幂等用例备注只有「接口文档§2；需求：X」 |

**配套的生成侧改造**（同样是源码驱动，不是手工修数据）：

| 改造项 | 原实现 | 现实现 |
|---|---|---|
| 正向断言锚点 | `回查 GET {path}/{id}`（拼出来的假地址） | `resolve_verify()`：按「动作段剥离 → 详情 → 祖先列表」顺序解析**真实存在**的回查目标；无目标时按响应类型断言 |
| 清理动作 | 一律写「调用对应删除接口」 | `cleanup_for()`：有 DELETE 才写删除；库存调整写「等量反向调整还原」；站点品牌/会员状态写「还原为操作前的值」；无删除接口的资源写「无需清理（专属测试数据）」 |
| 请求体 | 从 OpenAPI required 推（实际只有 8 个端点声明） | 源码 DTO 必填注解 + 控制器/服务层实际读取的字段（`req.getX()`）+ 实体业务字段，回落 OpenAPI |
| 测试数据键 | `data 非空` 之类占位 | `data.total 比提交前增加 1`（创建类）/ `data.status 为 <目标状态>`（状态类）/ `回查详情校验 error.code=NOT_FOUND`（删除类） |

**自测**：`lint_selftest.py` 已为 R31/R32/R33 各加"坏例必报"样例，离线规则总数 26 → 29。

**已知边界（不回避）**：源码大量返回**未类型化 Map**（`Result<Map<String,Object>>`），字段级断言无法静态推导。
这类用例的锚点保持"可执行但浅"（如 `回查 GET /admin/orders/{id} 校验 data 为对象且非空`），
深度提升需先补 VO 或引入执行期形状快照——属于第二层（把猜的变成查的）工作，不在此轮。

## 8. 第二层：幂等策略的源码化（2026-10-06）

> 背景：R35 落地前，78 条幂等用例中只有 18 条逐条读过源码，其余 60 条走"PUT→幂等 / DELETE→不存在 / POST→新建"的默认规则。
> 逐条核实后发现 **默认规则有 15 处是错的**（实测证据见下），说明"未核实的默认值"本身就是缺陷源。

### 判定口径

同一请求成功后再发一次会发生什么。DELETE 类以「对不存在的 id 再删一次」的返回码作为等价探测（该场景与"第二次删除"同路径）。

### 实测纠正结果（14 个 DELETE 端点）

| 语义 | 端点数 | 端点 |
|---|---:|---|
| **无存在性检查 → 第二次仍返回成功**（原默认判为 NOT_FOUND，**错**） | 9 | attributes / brands / categories / depts / dict-items / dicts / permissions / roles / favorites |
| 有存在性检查 → 第二次 NOT_FOUND（默认正确） | 3 | products / users / cart-items |
| 清空式删除，无副作用（幂等） | 1 | history |
| **源码现状 500**（不存在 id 触发 NPE，应为 NOT_FOUND，缺陷 D-3） | 1 | addresses |

### 其余纠正

| 端点 | 原默认 | 实际（源码依据） |
|---|---|---|
| `POST /api/after-sales` | 新建记录 | 同订单已有进行中售后 → `BAD_REQUEST`（AfterSaleService:99） |
| `POST /api/cart/clear-invalid` | 新建记录 | 无可清理项 → 无副作用（CartService:119） |
| `PUT /admin/stocks/adjust` | 幂等 | **增量生效**，两次调用扣两次（StockService:106） |
| 6 个认证端点（login×3 / refresh×2 / logout×2） | 新建记录 | 重复登录/刷新仅再签发令牌，登出仍成功 |

### 配套产出

- 策略表 `POLICY_OVERRIDES`（30 条）+ `DELETE_POLICY`（14 条）+ 方法族默认（带依据），每条含 `源码 文件:行 依据`；
- 断言随策略生成真实回查目标（复用 `resolve_verify`），不再出现"回查列表"这类无目标措辞；
- 出处写入用例**备注列**（可见、可查、可 lint）；
- **R35** 强制拦截无出处的幂等用例。
