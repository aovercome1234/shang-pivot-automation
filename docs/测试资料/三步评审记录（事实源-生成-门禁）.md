# 三步评审记录：事实源 / 生成 / 门禁

> 目的：回答"这三步的效果如何保证"。方法不是"看起来没问题"，而是**给每一步列出可核查断言，然后去证伪它**。
> 日期：2026-10-06。范围：`build_api_doc.py`（事实源）、`generate_cases.py` + `merge_business_cases.py`（生成）、`case_lint.py` + `lint_selftest.py`（门禁）。

---

## 0. 评审方法（三步通用）

| 步骤 | 它声称什么 | 证伪手段 | 判定证据 |
|---|---|---|---|
| 事实源 | "模型里每条事实都来自源码且与源码一致" | ① 覆盖率统计 ② 不变量检查 ③ 抽样回源码核对 | 覆盖率数字 + 越界条数 + 抽样结论 |
| 生成 | "清单是事实的正确投影，且模板不产生错误内容" | ① 确定性（连跑两次 diff）② 抽样：模型事实 → 用例字段 ③ 模板残留扫描 ④ 手工覆盖表审计 | diff 为空 + 残留计数 + 覆盖表条目数 |
| 门禁 | "fail 0 即代表清单可用" | ① 自测覆盖清单 ② 依赖缺失时的行为 ③ **历史缺陷归属统计**（哪个环节抓到的） | 规则覆盖率 + 假绿测试 + 查获率 |

**核心口径**：门禁的价值不看"拦了多少"，看"**它独立发现了几个缺陷**"。只看 fail 数会自我欺骗。

## 3. 门禁评审（结论最尖锐）

### 3.1 查获率统计（L0 → L2 全部 11 个缺陷的发现环节）

| 发现环节 | 条数 |
|---|---:|
| 抽样核对（人工抽 10 条对源码） | 3 |
| 逐条比对线上内容 | 3 |
| 源码证据 + 等价探测 | 1 |
| 覆盖率评审 / 模板残留扫描 / 同步失败排查 / 在线核对 | 各 1 |
| **门禁（lint）独立发现** | **0** |

**结论：门禁是"防回归闸门"，不是"缺陷发现器"。** 它保证已知问题类不再复发（每条新规则都源于一次真实事故），但不产生新知识。把质量寄托在 fail 0 上是错的——真正的发现来自抽样、比对和探测。

### 3.2 假绿风险（新修复）

原实现里，接口文档/领域词典/需求文档**缺失时规则静默跳过**（返回空集合 → 规则永不触发 → 仍报 fail 0）。
实测：临时移走 `领域词典.md` → 旧版报 "fail 0 warn 1"，**完全是假绿**。

**修复**：依赖缺失时直接拒绝出结论（exit 2），并打印规则启用状态：

```
✘ 门禁依赖缺失，拒绝给出结论（防假绿）：
   - 领域词典词表行（R27 依赖）：…/领域词典.md
```

正常时打印：
```
规则启用：接口清单 135 条（R14）、词典 48 词（R27）、需求 41 条（R28）、端点模型 135 条（R15/R31/R32/R33）
```

### 3.3 自测覆盖（新修复）

原 `lint_selftest.py` 把 R14/R28 标为"在线规则"跳过——但这两条只依赖**离线文档**，完全可以自测。
现在已纳入：**33 条离线规则全部有"坏例必报"样例**（仅 R19/R20 需联网，仍由 `--online` 覆盖）。

### 3.4 规则增强

- **R10 扩展**：原先只认 `id: 数字`，漏掉了裸数组 `[1]`（正是 §1 发现 1 逃逸的原因）。现已覆盖。

## 4. 结构性限制（本轮不修，如实记录）

1. **门禁无法判断"事实正确性"**：R31/R32/R33 只能检查"地址存在/端点在册/字段齐备"，断言**语义**是否正确（例如某个 status 目标值写错）仍需源码或执行验证。
2. **57 条 GET 用例锚点为浅层**（源码返回未类型化 `Map`），深度受限于 VO 缺失。
3. **170 条人工覆盖表**是事实源与生成之间唯一非源码驱动地带，会随接口演进漂移；建议每次接口变更后跑"生成 → lint → 抽样核对"三步。
4. **业务用例（50 条 BUS-*）无源码出处标注**：契约用例已做到"每条断言可回溯源码"，BUS 用例目前只标需求编号，未标源码依据——与 L2 对幂等策略的要求不一致，是下一轮可对齐的点。

## 5. 常态化建议（把评审变成流程）

| 时机 | 动作 | 产出 |
|---|---|---|
| 每次改 `build_api_doc.py` | 跑一次，看覆盖率与自检是否通过 | 覆盖率数字（写入报告） |
| 每次改生成器 | 连跑两次 diff；跑模板残留扫描 | diff 为空 + 残留为 0 |
| 每次改清单 | 离线 lint + 自测；**抽查 ≥10 条对源码**（不可省） | lint 报告 + 抽样结论 |
| 每次上传后 | `--online` 核对 + 逐条比对 3–5 条线上内容 | 在线报告 + 比对结论 |
| 每个新缺陷 | **先加规则，再修数据** | 新增 R 规则 + 自测样例 |

**单一最重要的一条**：把"抽查 10 条对源码"写进流程并强制执行。本轮 11 个缺陷有 7 个是抽样/比对抓到的，而门禁抓到 0 个。
