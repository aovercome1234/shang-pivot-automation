# 用例质量改造记录（第一层：让用例可执行）

> 触发：首轮 478 条用例离线 lint **fail 0**，但人工核查发现三类"形式合规、事实不成立"的缺陷。
> 本记录说明这三类缺陷的量化、根因、改造方式与复验结果。日期：2026-10-05。

---

## 1. 问题量化（改造前基线）

| 缺陷 | 条数 | 根因 |
|---|---:|---|
| 正向断言锚点指向**不存在的接口**（如 `回查 GET /admin/attributes/{id}`，该详情接口源码里没有） | **77** | 生成器把"无路径参数的端点"统一拼成 `原路径 + /{id}` 当回查目标，未校验该拼接结果是否真实存在 |
| 清理指令引用**不存在的端点**（如 `调用对应删除接口`，而该资源根本没有 DELETE） | **53** | 清理模板按 HTTP 方法套用，未与真实端点集核对 |
| 请求体字段不足（1–2 个字段占 127/174，另有 6 条为 `{}`） | **127** | 字段来源只有 OpenAPI 的 `required`，而全项目仅 8 个写接口声明了 required |

三类缺陷 lint 全部拦不住：R29 只检查断言里有没有 `回查` 二字，R08 只检查清理里有没有动作词，R07 只检查字段非空——**它们检查形状，不检查事实**。

## 2. 改造方式（源码驱动，非手工修数据）

### 2.1 事实层：扩展 `build_api_doc.py` 产出 `endpoint-model.json`

| 新增事实 | 来源 | 用途 |
|---|---|---|
| `dto_required` / `dto_fields` | `@RequestBody` 类型对应的源码 DTO 类字段 + `@NotBlank/@NotNull/@NotEmpty` | 请求体必填字段（R33） |
| `biz_fields` | 控制器方法体 + 被调服务方法中**该请求体参数自身**的 `getX()` 调用 | 请求体业务字段（避免把无关服务的 getter 混入） |
| `resp_keys` | 控制器/服务方法体中的 `put("key", ...)` | 响应结构文档化（未用于断言，因含嵌套键噪音） |
| 端点全集（含归一化路径） | 源码注解解析 | R31/R32 的存在性判定 |

### 2.2 生成层：三个解析器替换模板拼接

| 解析器 | 规则 |
|---|---|
| `resolve_verify()` | 按「动作段剥离 → 资源详情 → **祖先列表逐级上溯**」顺序解析真实存在的回查目标；创建类优先列表（新建 id 在断言期未知） |
| `anchor_text()` | 删除 → `回查详情校验 error.code=NOT_FOUND`；状态类动作 → `回查详情校验 data.status 为 <目标状态>`；创建 → `回查列表校验 data.total 比提交前增加 1`；PUT → `回查列表校验目标记录关键字段与提交值一致` |
| `cleanup_for()` | 有 DELETE 才写删除；库存调整写「等量反向调整（changeQty 取负）还原」；站点品牌/会员状态写「还原为操作前的值」；无删除接口的资源写「无需清理（专属测试数据）」 |
| `build_body()` | 源码 DTO 必填 ∪ 服务层实际读取字段 ∪ 实体业务字段，回落 OpenAPI；id 类字段附具体列表接口的取值约定 |

无回查目标时（如 `POST /api/reviews` 响应是标量 id）新增专项覆盖：`ANCHOR_OVERRIDE` 为认证/文件/支付/评价等 16 个特殊端点写出**真实可查**的锚点。

### 2.3 门禁层：三条新规则 + 固定样例

| 规则 | 检查 | 依赖 |
|---|---|---|
| **R31** | 断言中的 `回查 <METHOD> <path>` 必须存在于接口清单 | `endpoint-model.json` |
| **R32** | 清理列中「调用」引用的端点必须存在 | 同上 |
| **R33** | 请求体（可解析为 JSON 时）必须覆盖源码必填字段 | `dto_required` |

`lint_selftest.py` 为三条规则各加「坏例必报」样例：离线规则 26 → **29 条**；
随后在同步验证中发现字段名泄漏问题，补 **R34**（请求体字段名合法性）：**30 条**。

## 3.1 同步验证中追加发现并修复的三处缺陷

改造完成后逐条对照禅道线上内容，又抓出三个问题——都是"生成器/工具自身的缺陷"，不是用例措辞问题：

| # | 缺陷 | 影响 | 修复 |
|---|---|---|---|
| 1 | **内部标记泄漏进请求体字段名**：为区分响应键，代码把 `put("key")` 记成 `@key` 存进同一个集合，未过滤 → 请求体出现 `{"@cartItemId": …, "@quantity": …}` | 6 条用例的请求体非法 | 模型侧过滤 `@` 前缀；新增 **R34** 机械拦截（字段名禁 `@` 前缀与中文） |
| 2 | **嵌套 DTO 类解析不到**：`@RequestBody AddressService.AddressReq` 这类"外层类.内部类"写法，按简单类名查文件查不到 → 字段事实为空，请求体只剩 1 个字段 | 11 个写接口（地址/出入库/售后等）请求体过薄 | `@RequestBody` 正则支持 `A.B` 形式；`dto_facts()` 支持在外层类文件中定位内部类区块 |
| 3 | **带包名的类型比较失败**：`java.math.BigDecimal` 未去包名 → 金额字段被填成字符串 | 金额类字段取值类型错误 | 类型比较前 `split(".")[-1]`；顺带按业务域修正 `type` 字段取值（售后 `REFUND` / 出入库 `PURCHASE_IN` / 属性 `SPEC`） |

发现方式值得记录：这三条**都不是 lint 报出来的**，而是"改造完成后回禅道逐条比对内容"时肉眼发现的——
再次印证 §1 的结论：机械门禁保证形状，**内容正确性必须靠人比对或执行验证**。

## 4. 改造中顺带修掉的工具缺陷

**`zentao_sync.py` 的会话失效判定过宽**（会静默崩溃）：

```python
if "用户登录" in response.text:   # ← 用例标题/步骤里出现该词即误判
    self.login()
```

尚品汇用例 `POST_ADMIN_AUTH_LOGIN-003` 的标题是「管理员**用户登录**_缺少必填参数_提示参数错误」，
且创建用例后禅道会把标题回显在响应里 → `_post_case` / `case_records` 误判会话失效 → 对**已登录会话重复登录** →
禅道返回非 JSON 页面 → `RuntimeError: ZenTao login did not return JSON`。

**修复**：新增 `_session_lost()`，改按**响应 URL 是否被重定向到 `/user-login`** 判定（辅以禅道显式标记 `登录已超时` / `"load":"login"`），
全库 5 处文本级判定统一替换。这类缺陷与具体项目无关，凡是标题含「用户登录」的用例都会触发。

## 5. 仍然存在的边界（不回避）

1. **未类型化 Map 响应**：源码大量返回 `Result<Map<String,Object>>`，字段级断言无法静态推导。此类用例的锚点保持"可执行但浅"
   （`回查 GET <真实详情> 校验 data 为对象且非空`）。深度提升需先补 VO，或引入执行期响应形状快照。
2. **幂等策略仍有启发式**：78 条幂等用例中仅 18 条逐条读过源码；其余按 PUT→幂等 / DELETE→不存在 / POST→新建的默认规则，
   尚未逐条加源码出处标注。
3. **用例尚未执行**：本层解决的是"可执行性"，不是"正确性证明"。真正的质量证据仍来自执行（第三层）。

# 第二层：把猜的变成查的（2026-10-06）

> 目标：消除"无源码依据的默认判断"，并提升断言深度。验收标准：幂等策略 100% 带源码出处、状态类接口断言具体状态值、新规则锁死、门禁全绿、禅道同步完成。

## L2-1 幂等策略源码化

**做法**：先写证据提取器（对 60 个启发式端点从控制器 + 被调服务方法中抓判定行），再对 14 个 DELETE 端点做**等价探测**（对不存在的 id 再删一次，其返回码即"第二次删除"的语义），最后逐条编码出处。

**结果：78/78 幂等用例带源码出处（改造前 18/78）**，其中 **发现并纠正 15 处默认策略错误**：

| 类别 | 端点数 | 原默认 → 实际 |
|---|---:|---|
| DELETE 无存在性检查（第二次仍成功） | 9 | notfound → **idempotent_delete** |
| 售后重复申请 | 1 | new_record → **conflict_aftersale**（BAD_REQUEST） |
| 购物车清理失效项 | 1 | new_record → **idempotent_nolist** |
| 库存调整（增量语义） | 1 | idempotent → **accumulate_stock** |
| 认证类（login/refresh/logout） | 6 | new_record → **login_repeat / refresh_repeat / logout_repeat** |

出处写入用例备注列，新增 **R35** 机械拦截无出处用例。

## L2-2 断言深度

| 指标 | L1 后 | L2 后 |
|---|---:|---:|
| 状态值精确断言（`data.status 为 X` / `status 等于提交值`） | ~10 | **35** |
| 幂等用例断言绑定真实回查目标 | 部分 | **78/78** |
| 浅锚点（可执行但非字段级） | 57 | 57 |

浅锚点未减少但**分布已收敛**：57 条**全部是 GET 用例**（源码返回未类型化 `Result<Map<String,Object>>`），写操作类用例（POST/PUT/DELETE）浅锚点为 **0**。
继续加深需要补 VO 定义或引入执行期响应形状快照——属第三层工作，本轮不做，不用更浅的措辞假装达标。
