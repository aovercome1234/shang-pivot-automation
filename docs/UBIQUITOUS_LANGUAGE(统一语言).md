# UBIQUITOUS_LANGUAGE — 统一语言

> 本文件由 `ubiquitous-language` 技能产出，是项目术语的唯一来源。所有产出（spec、ticket、代码命名、测试名、issue 标题）必须用本表规范词，不漂移到同义词。
> 维护：发现新概念或歧义 → 记给 `domain-modeling`，在本表补充或消歧。

## 歧义消解（优先看这一节）

| 含混词 | 在本项目的两种含义 | 规范用法 |
|---|---|---|
| **Agent** | ① AI 智能客服（大模型+RAG）② 人工客服坐席 | ① 用「智能客服 / 智能体」② 用「坐席」。禁用裸 "Agent" 指代人 |
| **用户** | ① 后台管理系统用户 ② C 端购物顾客 | ①「后台用户」②「顾客」。代码：`AdminUser` vs `Customer` |
| **商品** | ① 可售卖实体（同款不同规格）② 具体规格单品 | ①「商品 / SPU」②「规格单品 / SKU」。禁用裸"商品"指代 SKU |
| **下单** | "提交订单" "生成订单" "创建订单" | 统一「提交订单」。代码 `submitOrder` |
| **支付** | 真实渠道 vs 沙箱模拟 | 沙箱阶段一律「沙箱支付」；真实渠道用「渠道支付」 |
| **工单** | 客服工单 vs 售后工单 | 客服用「客服工单(`Ticket`)」；售后用「售后单(`AfterSale`)」。不混用 |
| **库存** | 可售库存 vs 锁定库存 vs 实物库存 | 明确：`availableStock` / `lockedStock` / `physicalStock` |

## 电商业务术语

| 术语 | 英文/代码 | 定义 |
|---|---|---|
| 商品 | SPU | 标准产品单元，同款不同规格的集合，如"iPhone 16" |
| 规格单品 | SKU | 库存计价的最小单位，如"iPhone 16 256G 蓝色" |
| 类目 | Category | 多级商品分类树 |
| 品牌 | Brand | 商品品牌 |
| 属性 | Attribute | 规格（影响 SKU）或参数（不影响 SKU，仅展示） |
| 购物车 | Cart | 顾客临时的加购集合，含多个购物车项 |
| 购物车项 | CartItem | 购物车中某 SKU + 数量 |
| 订单 | Order | 顾客提交的交易单，含多个订单项 |
| 订单项 | OrderItem | 订单中某 SKU + 数量 + 成交价 |
| 订单状态 | OrderStatus | 待付款/待发货/待收货/已完成/已关闭（含取消、超时关单） |
| 沙箱支付 | SandboxPayment | 模拟支付渠道，回写订单为已支付，无真实资金 |
| 优惠券 | Coupon | 满足规则可抵扣的券，含领取/核销 |
| 促销 | Promotion | 满减/折扣/限时等活动 |
| 售后单 | AfterSale | 退款/退货退款申请单，独立于订单状态机 |
| 评价 | Review | 顾客对已完成订单的商品评价，含图文 |
| 地址 | Address | 顾客收货地址，含默认地址 |
| 物流 | Shipment | 发货单，含承运（模拟）与轨迹 |
| 收藏 | Favorite | 顾客收藏的 SPU |
| 足迹 | BrowseHistory | 顾客浏览过的 SPU |

## 状态机规范

### 订单状态机（OrderStatus）
`待付款 →(支付成功)→ 待发货 →(发货)→ 待收货 →(确认收货)→ 已完成`
`待付款 →(超时/取消)→ 已关闭`
`已完成/待收货 →(申请售后)→ 产生售后单 AfterSale`

### 售后单状态机（AfterSaleStatus）
`待审核 →(审核通过)→ 退款中 →(退款完成)→ 已完成`
`待审核 →(拒绝)→ 已拒绝`
`已拒绝 →(顾客改申诉)→ 待审核`

### 客服会话状态机（ChatSessionStatus）
`进行中(智能客服) →(转人工)→ 排队中 →(坐席接入)→ 进行中(人工) →(结束)→ 已结束`
`进行中(智能客服) →(解决)→ 已结束`
