# 测试体系增强：使用说明（2026-10-30）

本文件对应 9 项体系增强的落地形态与日常用法。所有命令均在 `pytest_automation/` 下执行；
默认环境 `TEST_ENV=dev`（本地后端 8086），需要管理端凭据时注入 `ADMIN_PASSWORD`。

## 1. 用例治理：注册表 / 评审 / 门禁

```bash
python3 scripts/export_cases.py          # 稳定编号（旧号优先，新增才分配）
python3 scripts/review_cases.py          # 生成评审单 artifacts/review/case-review.{md,csv}
python3 scripts/review_cases.py --apply  # 回填 data/case_review.yaml
python3 scripts/review_cases.py --check  # CI 门禁（P0 债务默认告警，--strict-p0 阻断）
python3 scripts/case_quality_gate.py     # 元数据/端点方法/写接口 DB 覆盖/硬编码/评审
```

- 注册表：`data/case_registry.json`（case_id、nodeid、content_hash、first_seen/last_seen、status）。
- 评审台账：`data/case_review.yaml`，存量 750 条标记 `legacy(auto)`，新增/内容变更必须 approved。
- 门禁白名单：`data/quality_gate_allowlist.yaml`（405 等系统级校验用例）。

## 2. 写接口完备性（请求 → DB）

- 契约：`data/write_contracts.yaml`，构建产物 `artifacts/write-contracts.json`（23 个写端点）。
- 实现：`helpers/db_contract.py` 的 `verify_write/verify_deleted`，按响应 ID、自然键或路径参数定位行。
- 用例：`tests/api/test_write_persistence.py`、`test_admin_crud_roundtrip.py`。
- 覆盖口径：覆盖率页显示“写接口 DB 断言 33/68（10 个认证/令牌接口不适用），链路方法覆盖 230/465”（其余写端点尚无契约/专项用例）。
- 方法校验：用例真实请求方法必须与端点模型一致，由 `build_coverage_matrix.py` 汇总。

## 3. 缺陷单与代码定位

```bash
python3 scripts/build_defects.py --report-dir artifacts/allure-report
python3 scripts/build_defects.py --zentao-dry-run    # 生成禅道 payload（不发送）
```

- 输入：`ext/data/api-matrix.json`（请求/响应/traceId 日志）。
- 定位：日志中首个非框架/非过滤器堆栈帧 → `文件:行`；无应用堆栈时按端点映射到
  `Controller#方法`（标注 `source=endpoint`）。
- 输出：`defects/<run_id>/<case>.md`、`defects/<run_id>/index.json`、报告 `ext/data/defects.json`。
- 报告：接口列表失败行可展开日志；「缺陷」页可下载缺陷单。

## 4. 覆盖率

静态矩阵（每轮）：

```bash
python3 scripts/build_coverage_matrix.py
```

- 135/135 接口有用例、链路节点 475/475、写接口 DB 断言 33/68（10 个认证/令牌接口不适用），链路方法覆盖 230/465、方法校验 135/135。
- 数据写入 `ext/data/coverage.json`，报告「覆盖率」页。

运行时行覆盖（夜间）：

```bash
bash scripts/start_backend_jacoco.sh --build   # 重启后端，agent 端口 6300
.venv/bin/python -m pytest -m api -q --alluredir=artifacts/allure
bash scripts/jacoco_dump.sh --reset
.venv/bin/python scripts/jacoco_report.py

```

详见 `docs/运行时覆盖率-JaCoCo.md`。限制：一次运行的总覆盖率，不做接口级切分。

## 5. 中间件：MQ 与 Redis

MQ 拓扑（Flyway V21）：

| 项 | 值 |
|---|---|
| 交换机 | `commerce.order.event`（direct） |
| 路由键 | `order.paid` |
| 主队列 | `commerce.order.event.queue` |
| 死信 | `commerce.order.event.dlx` → `commerce.order.event.dlq` |
| 幂等表 | `commerce.order_event_log`，唯一键 `(order_id, event_type)` |

启动：`cd backend && docker compose up -d rabbitmq`（管理台 `http://127.0.0.1:15672`，guest/guest）。

用例：

```bash
pytest tests/api/test_mq_order_events.py -q   # 支付事件落库、重复投递幂等、DLQ
pytest tests/api/test_redis_state.py -q       # SMS TTL/冷却、登录锁定、JWT 黑名单
```

MQ 测试依赖 `pika>=1.3`；Redis 测试依赖 `redis>=5.0`，均已在 `requirements.txt`。
登录失败计数与验证码冷却会互相影响并行用例，文件级标记 `serial`。

## 6. UI 多浏览器

```bash
# 推荐：并行 + 有头（默认）
ADMIN_PASSWORD=... bash scripts/run_ui_parallel.sh

# CI/无显示器：无头
UI_HEADED=0 bash scripts/run_ui_parallel.sh
```

脚本会为每个浏览器启动独立 pytest 进程（默认 Chromium+Firefox），进程内 3 worker；
有头模式会显示实际浏览器窗口，便于观察页面行为。两个进程必须使用独立 `--basetemp`。

- 每个浏览器一个 pytest 进程，**并行执行**；默认 `--headed` 有头展示，`UI_HEADED=0` 切无头；
- 必须各自指定 `--basetemp=.pytest_tmp-<browser>`，
  否则 xdist 会因共享 basetemp 冲突直接 INTERNALERROR。
- 不要叠加 pytest.ini 默认 `--browser=chromium`，用 `-o addopts=...` 覆盖，避免 `chromium0/chromium1`。
- 报告「UI 自动化 → 浏览器矩阵」按用例 × 浏览器展示状态/耗时；Allure Environment 显示浏览器数量。
- WebKit 在本机 `new_page()` 挂起（与 xdist 无关，单 worker 复现），默认只跑 Chromium+Firefox；
  其他环境可用 `UI_BROWSERS` 扩展。

## 7. 跨轮历史与知识库

```bash
python3 scripts/finalize_run.py     # 多次 pytest 后合并 results.json / run-manifest.json
python3 scripts/archive_run.py      # 归档到 artifacts/history/<run_id>/
python3 scripts/case_history.py     # 生成 ext/data/history.json（新增/删除/修改/结果迁移）
python3 scripts/build_knowledge_index.py
python3 scripts/kb_search.py "订单 幂等" --kind case
```

知识库为 SQLite FTS5：用例/端点/链路/字段映射/缺陷/历史，每条带 commit 与 baseline；
FTS 对中文按整词切分，检索不到时自动退回 LIKE 子串匹配。

## 8. CI 夜间流水线

- GitHub Actions：`.github/workflows/nightly-pytest.yml`（cron `0 18 * * *` UTC = 02:00 北京时间）。
- 可移植脚本：`scripts/ci/nightly.sh`，支持 `MODE=full|affected`、`SINCE=origin/main`、`SKIP_UI=1`。
- 选测：`scripts/select_tests.py --since origin/main`，git diff → Java 类/迁移表 → 端点 → 用例；
  无命中时回退 smoke。
- 夜间产物：报告、runs/history、缺陷单、质量门禁、`artifacts/ci/nightly-summary.json`。

## 11. 报告界面（2026-10-30 下午）

### 11.1 UI 多浏览器并行

```bash
# 两个浏览器同时跑，各自 3 worker；务必使用独立 basetemp
for b in chromium firefox; do
  pytest -m ui -q -n 3 --dist loadscope --browser "$b" \
    -o addopts="--tb=short --strict-markers --basetemp=.pytest_tmp-$b --reruns 1 --reruns-delay 1" \
    --alluredir=artifacts/allure &
done
wait
```

- 并行进程共享 `artifacts/allure`，结果 UUID 不冲突；跑完 `finalize_run.py` 合并为一份口径；
- `finalize_run.py` 同时写 `environment.properties`，Allure 首页 Environment 可见
  `UI.Browsers` / 每浏览器用例数 / 并行方式；
- WebKit 本机 `webkit.launch()` 后 `new_page()` 挂起（非 xdist），默认只跑 Chromium+Firefox；
  其他环境可 `UI_BROWSERS="chromium firefox webkit"` 扩展。

### 11.2 分类统计的 500 日志

- 数据源：Allure 结果中的「后端日志（500）」附件，缺失时回退「按 traceId」附件；
  附件仍无堆栈时，用构建期 `trace_excerpt` 兜底；
- 展示：分类统计页底部「500 错误日志」，一行一个失败点（用例/接口/分类/HTTP/业务码/traceId）；
- 点击「查看日志」打开抽屉，完整堆栈 + 复制按钮；
- `diagnose._log_files()` 同时搜索 `backend/logs`、`pytest_automation/logs` 和当前目录，
  并按修改时间倒序、排除 access 日志——后端从不同工作目录启动时也能取到应用日志。

### 11.3 测试点多标签分类

- 每个测试点带 `dimensions`（主分类保留在 `dimension`）：
  `DB校验`（落库/CRUD/不变量）、`请求方式校验`（契约矩阵）、`Redis校验`、`MQ校验`；
- 列表与抽屉显示多枚 `dim-tag`，抽屉分类下拉按任一标签过滤；
- 分类统计柱状图按多标签计数（图下注明可重复计数），饼图按主分类保证 100%；
- 请求方式仅在契约矩阵打点级标签；接口级方法一致性仍看覆盖率页 `methodChecked`。

### 11.4 覆盖率明细跳转

- `allure_report.sh` 把 `artifacts/jacoco/html` 复制到报告 `jacoco/html`，修复 404；
- 覆盖率页「运行时行覆盖率（按包）」的包名与「查看」均可跳到 JaCoCo 对应包页面，
  顶层「HTML 明细」跳到 JaCoCo 首页。

### 11.5 缺陷与下钻体验

- 缺陷页：用例列显示测试标题（去编号），接口列只留路径，失败摘要去除 `AssertionError`；
  代码位置取堆栈最底层应用帧（业务异常落到 Service），悬浮显示代码片段；缺陷详情展示仓库地址、
  本地/远端分支、运行 Commit、该行最后修改 Commit 与作者，先展示调用链再展示代码；报告内缺陷单为 UTF-8 HTML（`../defects/<run>/<file>.html`），
  `.md` 仅保留在仓库缺陷库供归档/禅道。
- 分类统计下钻：在「失败原因」后新增「错误日志」列，仅对含后端日志的失败点显示「查看日志」，
  点击打开与 500 日志面板相同的抽屉。

### 11.6 DB 校验补充

新增契约与断言：`PUT /api/addresses/{id}/default`、`DELETE /api/addresses/{id}`、
`DELETE /api/cart/items/{id}`、`PUT /admin/reviews/{id}/status`、
`POST /admin/after-sales/{id}/audit`；写接口 DB 断言 22/78 → 33/68（10 个不适用）。

### 11.7 接口维度覆盖率与组件校验

- 覆盖率明细新增「组件校验」列：Redis/MQ 相关接口显示“已校验”或“待补”，KPI 汇总 9/9；
- 「DB 落库断言」区分三种状态：已覆盖、不适用（认证/令牌接口，悬浮显示原因）、待补（用例触达但无落库断言）；
- 每行「链路」按钮打开抽屉，按 Controller → Service → 跨上下文 → 数据表展示静态调用链；
- 新增 Redis 用例：会员/管理端 refresh 吊销、管理端 logout、/api/auth/phone 别名；
- 新增 DB 契约/用例：会员状态、权限 CRUD、订单取消/确认。

### 11.8 方法级链路与补充建议

- 覆盖率明细的「链路方法」按钮打开方法级抽屉：Controller#method → Service#method → Mapper#method → 数据表；
- 点击链路中的类/方法节点，只展开该类在**当前接口链路中实际调用**的方法（不展示无关方法），并高亮当前方法；
- 抽屉顶部「未完全覆盖方法」列出链路中所有部分/未覆盖方法（不止当前类），点击可切换；
- 点击方法行继续展开逐行覆盖（行号/源码/状态），并直接列出未覆盖行号；
- 补充建议会带上未覆盖行号和对应源码片段，例如“第 77-78 行：as.setStatus("REJECTED")”。
- JaCoCo 镜像同时放在报告 `ext/jacoco`，类报告链接不再受根路径差异影响；
- 方法覆盖来自 JaCoCo XML（行覆盖状态：已覆盖/部分/未覆盖），文件行号可对照源码；
- 表格新增「补充建议」，对 JaCoCo 未/部分覆盖的方法给出补用例建议；
- KPI 新增「链路方法覆盖」230/465（49.5%），行覆盖 72.99%；
- 本轮依据未覆盖方法补充了认证 refresh/logout、权限 CRUD、会员状态、订单确认等用例。
