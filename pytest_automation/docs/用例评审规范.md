# 用例评审规范（pytest_automation）

## 1. 台账与状态

- 台账：`data/case_review.yaml`，键为稳定编号（`API-ORDER-001` 等）。
- 状态：`draft` / `reviewed` / `approved` / `rejected` / `legacy(auto)`。
- 每条记录保存 `content_hash`（由 title/verify/params/priority/file 计算）。

## 2. 触发规则

| 场景 | 要求 |
|---|---|
| 新增用例 | 必须 `approved` 后才能进主分支（本地可用 `--allow-new` 临时放行） |
| 已有用例内容变化（`content_hash` 变化） | 必须重新评审 |
| P0 用例 | 默认全评；夜间门禁 `--strict-p0` 阻断未评审 |
| 存量用例 | 一次性登记 `legacy(auto)`，内容不变即豁免；修改后失效 |

## 3. 抽样

- P0：100%；P1：30%；P2：10%；种子固定（20261029）保证可复现；
- 新增/修改用例不受抽样限制，全部进入评审单。

## 4. 流程

```bash
python3 scripts/export_cases.py                     # 1. 更新用例库/注册表
python3 scripts/review_cases.py                     # 2. 生成 artifacts/review/case-review.md
# 评审人填写结论后：
python3 scripts/review_cases.py --apply conclusions.json
python3 scripts/review_cases.py --check             # 3. 门禁（CI）
python3 scripts/review_cases.py --check --strict-p0 # 夜间严格模式
```

`conclusions.json` 格式：`{"API-ORDER-001": {"status": "approved", "reviewer": "张三", "comment": "..."}}`

## 5. P0 评审债

当前存量 P0 中仍有 65 条 `legacy(auto)`，门禁默认只告警；夜间 `--strict-p0` 会阻断。
治理方式：按模块分批人工复核，`--apply` 回填后债务清零；不要用 `--refresh-legacy` 掩盖内容变化。

## 6. 与质量门禁的关系

`case_quality_gate.py` 负责结构/规范检查（元数据、编号、方法、DB 断言、硬编码资源），
`review_cases.py` 负责人工结论；两者都通过才允许合并。
