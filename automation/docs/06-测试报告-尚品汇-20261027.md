## 3. 测试策略与准入准出

### 3.1 测试策略

采用风险驱动的测试金字塔：

```
        ┌─────────────────────┐
        │  E2E（1）           │  完整购买旅程
        ├─────────────────────┤
        │  UI（12）           │  关键页面与用户行为
        ├─────────────────────┤
        │  API（21）          │  契约、规则、状态机、权限
        └─────────────────────┘
```

- **API 优先**：运费、幂等、库存、支付、订单状态机、权限等规则用 API 验证，执行快、定位准；
- **UI 只测用户可见行为**：登录、搜索、加购、结算、支付、订单取消、后台关键页面；
- **E2E 只保留 1 条**：覆盖最有价值的完整购买旅程，避免端到端用例膨胀导致不稳定；
- **数据隔离**：每个写场景使用唯一会员，登记资源 ID 并精确清理。
