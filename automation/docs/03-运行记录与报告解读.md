## 6. 本次调试中发现并修复的问题

这些问题不是“框架跑不起来”的琐碎错误，而是企业落地时容易反复踩的坑，已写入代码注释。

| # | 现象 | 根因 | 修复 |
|---|------|------|------|
| 1 | 所有场景在 Allure 插件初始化时报 `NoSuchMethodError: Location.getLine()` | Allure 2.x 的 `allure-cucumber7-jvm` 编译时依赖 Cucumber 7 的 messages 类型；Cucumber 8.0.4 把 `getLine()` 返回类型改为 `long` | 降到 Cucumber 7.20.1 + JUnit Platform 1.11.4（Allure 官方验证组合） |
| 2 | 预检 API 通过，但商城/管理端 `HttpTimeoutException` | JDK `HttpClient` 默认 HTTP/2，Vite 对明文 h2c 升级处理不友好 | `EnvironmentProbe` 固定 `HTTP_1_1` |
| 3 | 所有路径断言失败，实际 URL 明明正确 | Playwright 把 Java `Pattern` 序列化为 JS 正则，JS 不支持 `\Q...\E` | `BasePage.expectPath` 改为普通字面量拼接 |
| 4 | 加购按钮 15 秒超时，截图里按钮明明存在 | “请选择规格”提示层与规格层都是 `.pop-panel`，`last()` 命中提示层 | 锁定 `.pop-panel.spec-layer` |
| 5 | 取消勾选后仍显示“已选 1 件” | Vant 4 选中态在 `aria-checked` 与 `.van-checkbox__icon--checked`，不在根 class | 按 `aria-checked`/icon 判断 |
| 6 | 管理端登录后等待“工作台”标题超时 | `.page-title` 是“上午好，超级管理员”，“工作台”在副标题 | 等待 `.stats .stat-value`，再断言页面含“工作台” |
| 7 | 应付金额断言失败，实际 `¥7999.00` | 金额带货币符号和千分位 | 断言前去掉 `¥/￥/,` |
| 8 | 验证码错误场景偶发“发送过于频繁” | 演示会员短信有 60 秒冷却，场景复用同一手机号 | 负向登录也使用唯一手机号 |
| 9 | 下单契约校验失败，实际 `orderNo=O2026...` | Schema 写成 `^SO` | 改为 `^O[0-9]{10,}` |
| 10 | 管理看板“字段应为数字”失败，实际 `"3"` | 后端把 Long 统一序列化为字符串 | 接受数字字符串并校验 `\d+` |
| 11 | `run-summary.json` 只有 32 条，实际 33 | Scenario Outline 两个 Examples 行同名，Map key 冲突 | key 追加递增序号 |
| 12 | Allure 结果散落在 `automation/allure-results` | 缺少 `allure.properties` | 显式配置 `target/allure-results` |
