## 4. 缺陷清单

| ID | 级别 | 场景 | 期望 | 实际 | 证据 |
|----|------|------|------|------|------|
| DEF-001 | P1 | 管理员对已支付订单发货 | 200 / 发货成功 | 500 系统异常 | trace `f53d332672524513a7f7764092a77fe7` |
| DEF-002 | P2 | 畸形 JSON 登录 | 400 参数错误 | 500 系统异常 | trace `af5121a4b55e4adc9c4f53b429966d07` |
| DEF-003 | P2 | 错误 Content-Type | 415/400 | 500 系统异常 | trace `80e5e13e92a547b8beedf91e0d418011` |
| DEF-004 | P2 | 购物车数量 1.5 | 40000 参数错误 | 50000 系统异常 | trace `8650bfc9cc8644a1b032d73d9f06c6d9` |
| DEF-005 | P2 | 购物车数量 "abc" | 40000 参数错误 | 50000 系统异常 | trace `994bbdcd820342f1a3d7cc3cca8281ed` |
| DEF-006 | P1 | 同一幂等键并发提交 | 两次同一订单号 | 一次 500 | Allure 附件 |
| DEF-007 | P1 | `alg=none` token | 401 | 500 + 默认错误体 | Allure 附件 |

### 4.1 重点缺陷说明

**DEF-001 发货单号冲突（P1）**

后端日志：

```
duplicate key value violates unique constraint "uk_in_out_bill_no"
Key (bill_no)=(SO202610270001) already exists.
```

影响：同一天第二次发货时出库单号冲突，发货接口 500，订单无法进入待收货。属于核心履约链路阻断。

**DEF-007 `alg=none` 令牌处理（P1）**

实际响应：

```json
{
  "timestamp": "2026-10-27T23:47:21.898+08:00",
  "status": 500,
  "error": "Internal Server Error",
  "path": "/api/cart"
}
```

问题：

1. 未拒绝非法 JWT，而是抛异常返回 500；
2. 返回 Spring 默认错误体，绕过统一 `{code,msg,traceId}` 契约；
3. 暴露 `timestamp/path` 等内部信息。

**DEF-002~005 输入健壮性（P2）**

畸形 JSON、错误 Content-Type、非整数数量均返回 500，而不是 4xx/统一业务码。说明 `HttpMessageNotReadableException`、`MethodArgumentTypeMismatch` 等未进入统一异常处理，客户端错误被当作服务端错误。

**DEF-006 并发幂等（P1）**

同一幂等键并发提交时，一次成功、一次 500。期望两次返回同一订单号，服务端只生成一笔订单。当前实现存在并发竞态（唯一键/幂等锁处理不完整）。

## 7. 结论与建议

1. **主回归 67/67 通过**，新增的边界、逆向、安全正向用例验证了：
   - 数量/分页/手机号/验证码/地址上限的边界行为；
   - 订单/地址 IDOR 被正确拒绝；
   - 管理员与会员 token 隔离有效；
   - 金额篡改被服务端忽略；
   - SQL 注入、CORS、基础安全响应头符合预期。
2. **7 个缺陷需修复**，其中 3 个 P1：
   - 发货单号冲突（DEF-001）；
   - 并发幂等 500（DEF-006）；
   - `alg=none` 500 + 默认错误体泄露（DEF-007）。
3. 建议修复顺序：DEF-001 → DEF-007 → DEF-006 → DEF-002~005。
4. 修复后回归命令：

```bash
mvn test -Dcucumber.filter.tags="@known-defect"
mvn clean test
```

5. 当前 `@known-defect` 是**隔离而非豁免**：主回归不因已知缺陷变红，但发布门禁必须要求该专项 0 失败。
